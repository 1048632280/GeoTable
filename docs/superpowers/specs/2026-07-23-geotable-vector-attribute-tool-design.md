# GeoTable 矢量属性表工具设计

日期：2026-07-23

## 目标

GeoTable 第一版是一个 Windows 桌面软件，用于查看和分析 `shp`、`kml`、`kmz` 点数据中的属性表。它的定位是“属性表查看器 + 搜索筛选统计工具”，不是完整 GIS 软件。

用户打开地理数据文件后，可以快速浏览样本点属性，模糊搜索字段值，按字段筛选，手动选择字段做分类统计，并基于点坐标离线识别国家和全球一级行政区。典型场景是搜索“茶树”相关样本后，统计这些样本分别位于哪些国家，再继续统计中国的云南、浙江等一级行政区各有多少样本点。

## 第一版范围

第一版支持：

- Windows 桌面运行。
- 打开 `shp`、`kml`、`kmz` 文件。
- 主要保证点数据；线和面数据可以读取属性表，但行政区识别不作为准确承诺。
- 显示属性表和字段列表。
- 全局模糊搜索字段值。
- 指定字段搜索。
- 字段值筛选和多条件筛选。
- 手动选择字段做分类统计。
- 显示总样本数和当前筛选结果数。
- 离线根据点坐标识别国家和全球一级行政区。
- 生成派生字段 `admin_country` 和 `admin_level1`。
- 使用派生字段继续筛选和统计。
- 导出当前筛选结果为 CSV。
- 行政区识别第一版只支持 WGS84 经纬度坐标。KML/KMZ 默认按 WGS84 处理；SHP 若不是经纬度坐标，第一版提示无法识别行政区，不做完整坐标转换。

第一版不支持：

- 地图预览。
- 空间编辑。
- 完整坐标转换能力。
- `tif` / GeoTIFF。
- 中国市县级行政区识别。
- 多图层工程管理。
- Excel 导出。
- 严肃法律边界判定。

## 核心用户流程

1. 用户打开一个 `shp`、`kml` 或 `kmz` 文件。
2. 软件读取要素属性表和点几何坐标。
3. 表格显示全部样本点。
4. 软件在导入完成后默认后台执行行政区识别，为点数据生成 `admin_country` 和 `admin_level1`；若用户取消或识别失败，可以手动重新运行。
5. 用户在全局搜索框输入关键词，例如“茶”。
6. 表格显示字段值中包含“茶”的记录，例如“茶”、“茶园”、“茶树”、“茶树（印度）”。
7. 用户选择统计字段，例如 `admin_country`。
8. 统计面板显示当前结果中各国家的数量和占比。
9. 用户点击“中国”，表格进一步筛选为中国样本。
10. 用户切换统计字段为 `admin_level1`。
11. 统计面板显示云南、浙江、福建等一级行政区的样本数量。
12. 用户导出当前筛选结果为 CSV。

## 技术路线

技术栈采用：

- Tauri：Windows 桌面壳、文件选择、后端命令桥接、打包。
- React + TypeScript：表格界面、筛选器、统计面板和交互状态。
- Rust 后端：地理文件读取、点坐标提取、行政区识别、导出数据准备。
- 离线行政区边界数据：内置全球国家边界和全球一级行政区边界。

第一版优先采用轻量解析路线，不直接依赖 GDAL。这样可以降低 Windows 打包和分发复杂度。架构上保留文件读取接口，后续如果遇到格式兼容性不足，可以替换或增加 GDAL 后端。

## 模块设计

### 文件导入模块

职责：

- 接收用户选择的 `shp`、`kml` 或 `kmz` 文件。
- 对 `shp` 读取几何和 DBF 属性表。
- 对 `kml` 读取 placemark、扩展属性和几何坐标。
- 对 `kmz` 先解压读取内部 KML。
- 输出统一的要素记录集合。

输出需要包含：

- 记录 ID。
- 原始属性字段。
- 点坐标，经度 `lon` 和纬度 `lat`。
- 文件元信息，例如文件名、记录数、字段列表。

### 表格数据模块

职责：

- 保存当前打开的数据集。
- 维护原始字段和派生字段。
- 提供前端表格可消费的数据结构。
- 支持十万行量级的内存浏览。

表格渲染必须使用虚拟滚动，避免一次性渲染全部 DOM。

### 行政区识别模块

职责：

- 加载内置的国家和全球一级行政区边界。
- 对每个点执行 point-in-polygon 判断。
- 给记录写入派生字段：
  - `admin_country`
  - `admin_level1`
- 对识别失败的记录保留空值或标记为 `Unknown`。
- 对非 WGS84 经纬度的 SHP 数据提示无法识别行政区，保留属性表浏览、搜索、筛选和统计能力。

边界数据用于统计分析，不用于法律边界判定。第一版不追求米级精度，优先保证常见样本点的国家和一级行政区归属可用。

性能策略：

- 边界数据使用简化版本。
- 通过包围盒预筛选减少多边形判断次数。
- 对十万点级别数据提供进度状态。
- 行政区识别任务应允许前端显示“识别中”和“部分失败”状态。

### 搜索筛选模块

职责：

- 支持全局模糊搜索。
- 支持指定字段搜索。
- 支持字段值筛选。
- 支持多个筛选条件叠加。
- 搜索和筛选基于当前数据集在内存中执行。

模糊搜索规则：

- 默认大小写不敏感。
- 对字符串字段执行包含匹配。
- 数字和布尔字段转成字符串后参与搜索。
- 空值不命中搜索。

### 统计模块

职责：

- 用户手动选择统计字段。
- 对当前筛选结果进行分类计数。
- 显示类别名称、数量和占比。
- 点击统计项后，将该类别加入筛选条件。
- 支持复制统计结果文本。

统计对象可以是原始字段，也可以是 `admin_country`、`admin_level1` 等派生字段。

### 导出模块

职责：

- 导出当前筛选结果为 CSV。
- 导出内容包含原始字段和派生字段。
- 使用 UTF-8 编码。
- 保留当前表格中可见的字段顺序。

## 前端界面

第一版打开后直接进入工作台，不做营销式欢迎页。

### 顶部工具栏

包含：

- 打开文件按钮。
- 当前文件名。
- 总样本数。
- 当前筛选结果数。
- 行政区识别状态。
- 导出当前结果按钮。

### 左侧字段与筛选面板

包含：

- 字段名搜索框。
- 字段列表。
- 原始字段和派生字段标识。
- 选中字段后的唯一值列表。
- 字段值筛选操作。
- 清除筛选操作。

### 中间主表格

包含：

- 属性表。
- 虚拟滚动。
- 全局模糊搜索框。
- 搜索范围选择：全部字段或指定字段。
- 表头排序。
- 派生字段列。

### 右侧统计面板

包含：

- 统计字段选择器。
- 类别、数量、占比列表。
- 点击统计项筛选。
- 复制统计结果。

## 数据结构

前端核心记录结构：

```ts
type FeatureRecord = {
  id: number
  geometry: {
    type: "Point"
    lon: number
    lat: number
  }
  properties: Record<string, string | number | boolean | null>
  derived: {
    admin_country?: string
    admin_level1?: string
  }
}
```

后端可以使用等价 Rust 结构，并通过 Tauri command 返回序列化后的数据。后续若切换到数据库或 GDAL 后端，前端仍消费相同结构或分页接口。

## 错误处理

需要明确处理以下情况：

- 文件格式不支持。
- `shp` 缺少配套文件。
- 文件无法读取或被占用。
- 属性表编码异常。
- KML/KMZ 内没有可用点要素。
- 几何不是点数据。
- 点坐标缺失或无效。
- 行政区识别部分失败。
- CSV 导出路径无权限。

错误信息应使用用户能理解的中文描述，并尽量说明下一步可做什么。

## 测试与验收

验收样例：

- 打开一个包含点要素的 `shp` 文件，表格显示属性字段和记录数。
- 打开一个 `kml` 文件，表格显示 placemark 属性和记录数。
- 打开一个 `kmz` 文件，能够读取内部 KML。
- 搜索“茶”时，能够命中包含“茶”的字段值。
- 在搜索结果中按字段做分类统计，数量和当前筛选结果一致。
- 行政区识别后，记录包含 `admin_country` 和 `admin_level1`。
- 筛选 `admin_country = 中国` 后，再统计 `admin_level1` 可以看到省级数量。
- 导出的 CSV 包含当前筛选结果和派生字段。

性能验收：

- 十万行级别数据可打开并浏览。
- 表格滚动不应因为 DOM 渲染全部行而卡死。
- 搜索和统计在十万行量级下保持可接受响应。
- 行政区识别可以显示进度，不应让界面无响应。
